The failure mode

A chat instruction is not a control.

An agent with a funded Base wallet can drain itself through loops, bad destinations, over-eager swaps, or prompt injection. Wallet SDKs sign what they are asked to sign. Something has to sit in front of that signature.

AllowLatch is that turnstile: hosted policy, deterministic gate, single-use allow-receipt. The LLM drafts and explains. It never overrides the verdict.

How it runs

Mandate in words. Verdict in code.

One path from owner intent to a signed transfer - with a hard stop in the middle.

  1. 01

    Owner mandate

    Limits, symbols, addresses, escalate threshold — in natural language.

  2. 02

    SERV Copilot

    Host Reasoning drafts MandatePolicy, surfaces conflicts, resists injection.

  3. 03

    engine.ts gate

    Deterministic ALLOW / DENY / ESCALATE. No policy applied → every spend is DENY.

  4. 04

    Receipt, then sign

    Single-use jti. AgentKit signs only after ALLOW. Timeout → DENY.

Rule: only an applied MandatePolicy counts. Local demo drafts and offline heuristics are not production enforcement. If you never Apply / Go live, there are no spending rules — and the agent must not move funds.

Production shape

How to run this with real money.

Middleware is not a vault. Use AllowLatch as a lock only when the signer path cannot skip the gate and the daily USDC cap also lives on-chain.

  1. Gated signer only

    createGatedAgentKit({ kind: 'site' }). No parallel raw sendTransaction. Prefer a session key / smart-account spender.

  2. AgentKit on-chain ceiling (required)

    For agents with Coinbase AgentKit / CDP: after Go live, Copy for my AI sets a daily USDC Spend Permission and reports it (hybrid_plan → hybrid_report). The gated kit will not consume a receipt until that binding matches the daily cap. Keep USDC on the owner Smart Account. This site does not ask you to connect MetaMask.

  3. Human confirms the draft

    SERV drafts; you Go live. Compilation residual risk is human review — the gate never lets the model invent ALLOW.

  4. Ordinary small balances

    SA + synced Spend Permission + durable Turso. No third-party audit yet. Reject / DENY → no receipt. Micro evaluates: buy_pack + packKey (~$0.008) instead of $0.025 every time.

SDK: recommendProductionShape() · agent.productionShape. Without gated kit + hybrid caps, this is a denial journal — not a physical lock.

Install

How you (and your agent) connect.

For owners of an AI agent with a Coinbase AgentKit / CDP wallet on Base. You do not run a server. You do not need SERV_API_KEY. Path: Simple rules → SERV Draft → Go live → Copy for my AI. This site is a turnstile for that agent — not a place to connect MetaMask and “lock” a personal wallet.

For you (human)

  1. Open Try the gate → fill Simple rules (daily cap + addresses) or write a mandate.
  2. Draft with SERV → review conflicts → Apply → Go live.
  3. Copy for my AI — paste into Cursor / Claude / your AgentKit agent (needs sessionSeal).
  4. Optional: AgentKit daily ceiling (right rail) — or let the agent follow hybrid_plan in the pack.

For your AgentKit agent

  1. Follow the Connect pack (or /api/host-info → primary.gateUrl).
  2. Owner already applied MandatePolicy (Go live). Keep sessionSeal.
  3. Required: createGatedAgentKit({ gate: { kind: 'site', … } }) before every spend.
  4. Optional: hybrid_plan → CDP Spend Permission → hybrid_report. Never take the funded treasury key.
  5. assertSpend alone is advisory. The gated kit consumes jti on ALLOW, then you may sign; else stop.

Live case · Base mainnet · 22 Sep 2026

SERV drafts. Code decides. Base settles.

Full product path: SERV Reasoning drafts the mandate → Go live on /api/gate → agent pays $0.025 x402 → deterministic DENY / ESCALATE / ALLOW → SERV explains the DENY → only ALLOW + a consumed receipt may sign on Base.

  1. 01 · Fund

    Owner tops up the agent wallet

    Spender 0x36fe…3645 held USDC + gas ETH on Base (earlier top-ups including 0x6e95…1816).

  2. 02 · SERV draft

    Plain language → MandatePolicy

    Budget $2 USDC on Base. Max $0.10 per transfer and $0.50 per day. Only allow transfers to 0x5cc0…6205. No swaps. Escalate above $0.05.

    POST /api/copilot (action draft) via SERV Reasoning — Multipath · prompt_guard · shadow — model gpt-5.4-mini, prompt allowlatch-draft-v1, ~15s. Ready-to-apply policy: lifetime $2 · day $0.50 · per-tx $0.10 · confirm above $0.05 · swaps off · single allowlisted destination.

  3. 03 · Go live

    Durable site gate

    Free same-site apply → policyId serv-live-1790076763, durable: true (Turso) + sessionSeal for the agent Connect pack.

  4. 04 · Paid checks

    Always-on /api/gate · $0.025 each

    Agent paid native Base USDC x402 to operator 0xa918…F677 (balance 0.495 → 0.57 USDC = three settlements). Not OpenServ payWorkflow — primary path is the Vercel gate.

    • DENY wrong destination → fee 0x3e3e…a0c6 · SERV explain (~25s): destination not on allowlist — verdict unchanged
    • ESCALATE $0.08 above $0.05 confirm → fee 0x4a78…c0f3 · not signed
    • ALLOW $0.04 + receipt → fee 0xa8ec…ae43 → signed transfer 0x399d…92b5
  5. 05 · Result

    Product invariants held

    SERV drafted and explained — never overrode allow/deny/escalate. engine.ts owned every verdict. Fees hit the operator wallet. Signature only after ALLOW + consumed allow-receipt. Same flow via Install below.
