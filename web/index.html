The failure mode

A chat instruction is not a control.

An agent with a funded Base wallet can drain itself through loops, bad destinations, over-eager swaps, or prompt injection. Wallet SDKs sign what they are asked to sign. Something has to sit in front of that signature.

AllowLatch is that turnstile: hosted policy, deterministic gate, single-use allow-receipt. The LLM drafts and explains. It never overrides the verdict.

How it runs

Mandate in words. Verdict in code.

  3. 03

  4. 04

    Single-use jti. AgentKit (or your wallet stack) signs only after ALLOW.

Integration

Keep your agent. Add the latch.

AllowLatch is the gate, not a replacement repo. Wire createGatedAgentKit (preferred) or assertSpend so the agent cannot call a raw signer in parallel. walletPrivateKey in the snippet is only the x402 payer — not necessarily the CDP signer.

Embed guide

Snippet drops into your AgentKit project. Demo Codespaces is optional - not a fork target. 

// walletPrivateKey = x402 payer only
await assertSpend({ intent, triggerUrl, walletPrivateKey })
// ALLOW + receipt → then sign via gated adapter
// timeout / DENY → refuse (fail-closed)
