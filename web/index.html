The failure mode

A chat instruction is not a control.

An agent with a funded Base wallet can drain itself through loops, bad destinations, over-eager swaps, or prompt injection. Wallet SDKs sign what they are asked to sign. Something has to sit in front of that signature.

AllowLatch is that turnstile: hosted policy, deterministic gate, single-use allow-receipt. The LLM drafts and explains. It never overrides the verdict.

How it runs

Mandate in words. Verdict in code.

One path from owner intent to a signed transfer - with a hard stop in the middle.

  1. 01

    Owner mandate

    Limits, symbols, addresses, escalate threshold — in natural language.

  2. 02

    SERV Copilot

    Host Reasoning drafts MandatePolicy, surfaces conflicts, resists injection.

  3. 03

    engine.ts gate

    Deterministic ALLOW / DENY / ESCALATE. No policy applied → every spend is DENY.

  4. 04

    Receipt, then sign

    Single-use jti. AgentKit signs only after ALLOW. Timeout → DENY.

Rule: only an applied MandatePolicy counts. Local demo drafts and offline heuristics are not production enforcement. If you never Apply / Go live, there are no spending rules — and the agent must not move funds.

Install

How you (and your agent) connect.

You do not run a server. You do not need SERV_API_KEY. Pick any path — all of them end at the same hosted gate before every spend.

For you (human)

  1. Open this site → write a mandate → Draft → review.
  2. Go live — policy stored on the server gate + real receipts.
  3. Connect your agent — copy instruction, code, or MCP.
  4. Or tell your agent in chat: “Connect to AllowLatch Gate on OpenServ and apply my mandate.”

For your agent

  1. Discover AllowLatch Gate (/allowlatch/i) or read /api/host-info.
  2. Apply the owner’s MandatePolicy once (apply_policy / paywall).
  3. Before every transfer / swap / x402 pay: assertSpend (or gated kit).
  4. ALLOW + receipt → may sign. DENY / ESCALATE / timeout → do not sign.

Live case · Base mainnet · Sept 2026

Real x402 fees. Real USDC transfer.

End-to-end as a user agent: site Go live → assertSpend on /api/gate ($0.025) → ALLOW + receipt → only then sign on Base.

  1. 01 · Fund

    Owner tops up the agent wallet

    Spender 0x36fe…3645 received USDC + gas ETH on Base (top-ups including 0x6e95…1816).

  2. 02 · Mandate

    Rules in plain language

    Budget $0.16 USDC on Base. Max $0.10 per transfer. Escalate above $0.05. Only transfer to 0x5cc0…6205. No swaps, no other contracts.

    No applied MandatePolicy → every spend DENY (fail-closed). Local drafts are not production enforcement.

  3. 03 · Paid gate

    Always-on gate · $0.025 per agent call

    Hosted AllowLatch Gate online. Agent paid with its own USDC; settlement to operator 0xa918…F677 (seen rising to 0.25 USDC across the session). Path: payWorkflow / assertSpend — not a local engine.ts bypass.

  4. 04 · Verdicts

    What the turnstile returned

    • ALLOW $0.04 after paid assertSpend + receipt → signed tx 0x3d9e…9c16 (also 0xc3b2…223f, 0x0447…d0c7)
    • ESCALATE $0.08 → not signed (above $0.05 human confirm)
    • DENY wrong destination / over max → not signed
  5. 05 · Result

    Product invariants held

    LLM never overrode the verdict. Fees hit the operator wallet. Signature only after ALLOW + allow-receipt. Same flow your agent should use via Install below.
